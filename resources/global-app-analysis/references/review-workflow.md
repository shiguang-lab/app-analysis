# 第 9 步证据交叉复核工作流

业务调研和 UED 共用本流程。第 5 步用[审查清单](review-checklist.md)设计覆盖，第 8 步生成交付物初版（业务报告/图册、Mermaid）和运行记录后进入 9.1。纯下载在第 4 步完成 APK 校验后交付。

## 9.1 准备证据并清点缺口

从原范围、场景、页面和证据清单为每个适用面列出应审项 ID，并写明本轮要读的文件（含交付物初版路径与任务目录下的内部复核记录，如 `review-notes.md` 或 `research-state.json`）。审查者必须用文件读取工具从磁盘打开这些文件，不能依据上下文或上一轮摘要；各项粒度应足以判断对应问题、分支或页面的证据是否齐全。

先查初版、流程图注释、清单和运行记录中标记为未查、未测、未走通、未用模拟数据、待确认、未知或含义相近的项，再检查未标记但缺少代码或运行证据的项。按问题、路由、页面或分支 ID 登记缺口及下一项确认动作。已有完整实测时可引用证据关闭“未用模拟数据”项。其余优先补证，可并行核查独立审查项。

## 9.2 分工并收齐本轮结果

按[审查清单](review-checklist.md)分派本轮适用审查面。只要当前客户端具备子 agent / 隔离会话能力（例如 Codex 的 `spawn_agent` 设 `fork_turns: "none"`、或其他客户端的等价子 agent 工具），每面**必须**新开隔离审查上下文并从磁盘读取当前文件，禁止在原审查子 agent 线程中续聊。先给原始问题、范围、原始证据入口和分工，让审查者独立枚举，再给初版、已知缺口和现有清单做比对。名额不足时依次启动。**仅当运行客户端本身完全不提供隔离上下文能力时**，主 agent 才可在当前会话按相同清单分面枚举与比对，并在内部记录与聊天正文中注明“运行环境无隔离工具，已按 9.2 分面兜底”。

每面按开审清单逐项回传结论、证据位置和判断依据，未解决的项关联缺口 ID。审查者核对每条拟判不可执行路径的必要前置条件、检查结果及原始证据。证据不足时记录为待补证并回 9.3。全部适用面交齐逐项结果后才进入 9.3 或复审；审查者结果不全时补齐该面，必要时使用当前会话复核。多个审查者并行只算一轮。分歧回查原证据，共用设备上的实测由主 agent 排队协调。

## 9.3 修正、补证或判定阻塞

按[完成条件](completion.md)分派缺口，合并同轮问题并按[回路预算](loop-budget.md)计数。缺实现或入口证据回第 5–6 步，缺交互或图片回第 7–8 步，图文矛盾同步修正并更新第 8 步初版。必要场景在 App 宿主执行，按[运行与 Mock](runtime-and-mock.md)处理登录、会话和数据条件。回填原清单，保留本轮审查记录；修正完成后回 9.1 重新审查，不能直接进入 9.5。需要外部输入或续批时按[阻塞判定](completion.md#真实阻塞与结论边界)记录并保留恢复点。

## 9.4 对当前文件重审

首审结束后至少独立再审一轮（全流程累计不少于 2 轮独立审查），即使首审没有发现。复审必须**新开隔离上下文**重新打开磁盘上的当前文件，按文件实际内容判断；修改事实、范围、流程图、页面或验收证据后，重新读取同一文件并从 9.1 重开 1 轮独立复审（累计≥2 轮且该次新复审通过即满足第 9 步出口），不能只重跑 10.4。按完整范围重新审定当前文件的全部应审项，保留未受修正影响的应审项 ID，并逐项记录原证据为何仍适用或引用新证据。阶段性结论也保留所有应审项及缺口。补测及主 agent 修正自检作为复审输入。复审中新发现问题回 9.3，直到最后一次修改后的文件通过。

## 9.5 检查第 10 步入口

放行前按[放行判据](rules.md#放行判据)逐条回答，任一为“否”就回 9.1，不要先进入定稿再补审；第 10 步定稿后交付前另按该表确认最终成品。

核对[完成条件](completion.md#第-9-步的完成门槛)，确认首审和独立复审覆盖当前初版的全部应审项、缺口已关闭或按阻塞规则记录。审查通过后进入第 10 步[报告审查](report-review-workflow.md)或[图册交付验收（album）](ued-workflow.md#交付验收与进度)；`10.4`/album 通过不是完成信号，若第 10 步修改过成品，交付前须再派 1 次独立复审读当前最终文件。真实阻塞或用户要求先看时，只对已核实范围审查并交付，剩余缺口保持开放。
