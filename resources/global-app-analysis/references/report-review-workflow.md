# 第 10 步业务报告审查工作流

第 9 步校验通过后，对第 8 步生成并审定的交付文件执行第 10 步检查与定稿。10.1–10.4 每一步都从磁盘重新打开当前文件，不得依据上下文或上一轮结论；将检查结果关联到最终文件和当前内容。阶段性报告也按同一流程验收其已核实内容。纯 UED 按[图册交付验收（album）](ued-workflow.md#交付验收与进度)执行。

## 10.1–10.4 检查项

| 环节 | 检查 | 通过判据 |
|---|---|---|
| 10.1 格式与规范 | 打开实际文件，查标题层级、正文、列表、表格、图注与术语；Markdown 用 Mermaid 代码块，HTML 内嵌实际渲染的 SVG；清理正文、附录、折叠区与仅用 CSS 隐藏的内部材料 | 与用户指定格式一致，离线所需依赖已打包 |
| 10.2 结构与阅读顺序 | 提取标题树或 DOM 章节树，对比默认总分结构；逐 App 查流程连续、阶段顺序与页面归属；补查结论回填所属阶段 | 章节树通过结构检查，导航与锚点指向本 App 正确层级 |
| 10.3 结论与正文 | 先读总览与各摘要首句；逐段核对一句话一判断；逐项对照第 9 步；清理取证状态表述 | 结论直接回答业务问题；图、正文、字段权限与图片同源 |
| 10.4 最终 UI 与可用性 | 桌面与手机尺寸打开交付文件；点击流程图节点验展开与定位；查图片加载、尺寸、长图可读与截图哈希；空目录断网复开 | 无溢出、缺图、渲染错误或 JS 错误；记录最终打开的文件 |

10.4 通过只说明成品可用，不是完成信号。

## 修改、重审与交付

| 发现的问题或改动 | 重审起点 |
|---|---|
| 格式、模板、交付类型或文件封装 | 回 10.1，按顺序复查后续环节 |
| 章节、顺序、层级或内容归属 | 回 10.2，复查受影响的正文和 UI |
| 只改措辞且事实含义一致 | 回 10.3，重新打开成品执行 10.4 |
| 只改样式、布局、资源加载或坏链接 | 回 10.4；牵涉章节归属或文件封装时回对应的更早环节 |
| 事实证据不足，或改变业务条件、结果、流程连线、页面状态或范围 | 回 9.1 重新审查，更新同一报告并审定后，从 10.1 开始 |

同一轮有多类改动时先合并，按[回路预算](loop-budget.md)记录返工，从最早受影响的环节重审。任何审查后对报告、图册或验收证据的修改，必须重新读取同一文件并确保改后有独立复审读过当前最终文件：若改动涉及事实、流程、范围或证据，回 9.1 重开 1 轮独立复审；若第 10 步仅改样式、布局、断网加载或纯措辞，按上表从对应 10.x 复查后，定稿前仍须新开 1 次独立复审读取当前最终文件，不能只重跑 10.4。

交付前按[放行判据](rules.md#放行判据)逐条回答，任一为“否”就跑对应环节；最后一次修改之后必须还有一次独立复审，自己重读、沿用旧审查线程或重跑脚本都不算。
